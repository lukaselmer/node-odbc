# Why some oxlint rules are off

`correctness`, `suspicious`, `perf` and `pedantic` all run as errors. The rules disabled in
`.oxlintrc.json` fall into three groups, and the reasons matter more than the list.

## Wrong for this package

- **`require-await`** — the validating methods (`connection.query`, `statement.bind`) are
  `async` precisely so that a bad argument rejects rather than throwing synchronously. The
  whole API is promise-based; a caller should never have to both `try`/`catch` and `.catch()`.
- **`no-await-in-loop`** — a connection processes one statement at a time, so the sequential
  awaits in `runInitialStatements` are the correct shape, not an oversight.
- **`import/no-nodejs-modules`** — this is a Node addon. It cannot run in a browser.
- **`unicorn/prefer-event-target`** — nothing here uses an emitter any more, but the rule
  would fire again the moment anything did, and `EventTarget` buys us nothing off the web.

## Style the repository does not follow

`no-ternary`, `no-nested-ternary`, `sort-keys`, `sort-imports`, `id-length`, `one-var`,
`func-style`, `capitalized-comments`, `no-magic-numbers`, `init-declarations`,
`max-lines-per-function`, `max-depth`, `prefer-named-capture-group`, `no-undefined`,
`promise/avoid-new`, `unicorn/filename-case`.

These are preferences, not defects. Sorting keys and imports in particular fights `oxfmt`
and makes diffs noisier than the code they describe.

## Kept deliberately

`typescript/no-explicit-any`, `no-non-null-assertion`, `consistent-type-imports` and
`explicit-function-return-type` are on because the point of the TypeScript conversion was to
stop guessing at the boundary between JavaScript and the addon.
